# Гайд команды: macOS, Linux, Windows

## 1. Подготовка

Распакуйте архив и откройте терминал **в папке `godnota`**, где лежат `go.work`, `README.md` и `docker-compose.yml`. В путях нет привязки к пользователю автора. Папки с пробелами поддерживаются.

Проверьте `go version`: требуется Go 1.26.5; `go.work` допускает 1.26+. На Apple Silicon используйте Go darwin/arm64, на Intel Mac - darwin/amd64, на Linux - сборку под архитектуру машины, на Windows - windows/amd64. Для native-запуска не нужны дополнительные языки или менеджеры пакетов.

Первый запуск загружает зависимости из Go proxy. После загрузки demo/E2E не требуют сети до внешних поставщиков. Protobuf уже сгенерирован и хранится в исходниках.

Не устанавливайте глобально `GOOS`/`GOARCH` для обычного запуска: команды должны выполняться для ОС вашего компьютера. Все команды ниже одинаковы в терминалах трёх ОС, если явно не сказано обратное.

## 2. Запуск и остановка

```text
go run ./cmd/dev run
```

Локальный runner собирает бинарные файлы под текущую ОС, проверяет свободные порты, создаёт `data/logs/`, запускает шесть сервисов и ждёт их готовности. Только после этого печатает URL. Если один процесс аварийно завершается, runner возвращает ошибку и останавливает остальные. Ctrl+C также останавливает дочерние процессы.

| Сервис | Порт по умолчанию | Назначение |
|---|---:|---|
| gateway | 8080 | публичный HTTP API и документация |
| travel-service | 50051 | подтверждение конфига, поиск, handoff |
| session-service | 50052 | контекст и владелец сессии |
| map-service | 50056 | маппинг конфига |
| route-service | 50057 | граница следующего этапа; склейка пока не реализована |
| provider-service | 50058 | поиск и нормализация частей |

AI/user/order-сервисы исходного каркаса не нужны для проверки нашей части и native-runner их не запускает. Compose сохраняет полный исходный набор сервисов. Ручки AI-диалога, профиля и оплаты не входят в проверенный сценарий.

Если порт занят, остановите **свой** другой стек либо используйте свободные порты:

```text
go run ./cmd/dev run -random-ports
```

Во втором терминале:

```text
go run ./cmd/dev smoke
```

При случайном порте: `go run ./cmd/dev smoke -url http://127.0.0.1:<напечатанный-порт>`. Smoke создаёт новый демо-аккаунт и новую сессию. Ожидаемый результат: `PASS` и четыре транспорта / одна гостиница.

Документация: `http://127.0.0.1:8080/docs`. HTTP `/health` - проверка gateway; runner дополнительно проверяет готовность остальных процессов. Журналы: `data/logs/<service>.log`.

## 3. Docker как одинаковое окружение

Windows/macOS: Docker Desktop с Linux-контейнерами. Linux: Docker Engine с Compose v2.24+. Сначала проверьте `docker info` и `docker compose version`.

```text
docker compose up --build --wait
docker compose ps
docker compose logs --tail 100
```

Публичный API - порт 8080. gRPC-порты контейнеров наружу не публикуются. Именованный volume `auth-data` сохраняет аккаунты. Для остановки достаточно `docker compose down`; эта команда не удаляет volume. Если нужен второй стек параллельно, используйте native-runner со свободными портами, чтобы не конфликтовать за 8080.

`go run ./cmd/dev smoke` проверяет контейнерный API, если Go установлен на хосте. Без Go можно пройти запросы из документации или Postman. Полная CI-проверка Docker после публикации будет запускать smoke автоматически.

## 4. Переменные окружения и live

Без ключей используйте demo. Для live создайте локальный `.env` копированием `.env.example` и заполните `TRAVELPAYOUTS_TOKEN`, `YANDEX_RASP_API_KEY`. Файлы `.env` не входят в Git и Docker build context.

```text
go run ./cmd/dev run -mode live
```

Runner читает `.env` **как данные**, без выполнения shell-команд. Можно указать `-env-file другой-файл`. Настоящие переменные окружения имеют приоритет перед значениями файла; адреса внутренних локальных процессов, порт и путь аккаунтов runner задаёт сам. `-mode` явно выбирает demo/live. В Docker режим задаётся `PROVIDER_MODE=live` в `.env`.

Для live в `config.resolved` нужны проверенные IATA/Яндекс-коды. Пример - `configs/examples/resolved_trip.kazan_weekend.json`; он соответствует Москве и Казани, его нельзя использовать для других городов. Автоматический геокодинг ещё не подключён. Коды должны быть проверены backend, а не угаданы моделью.

Отсутствие ключей/кодов/гостиничного API даёт структурированные ошибки, а не выдуманную выдачу. Внешние API в автоматических тестах заменяются управляемыми HTTP-серверами. Это подтверждает наш протокол обработки, а не работоспособность конкретного ключа или доступность стороннего сервиса.

## 5. Минимальный пользовательский сценарий

1. `POST /api/auth/register` с email и паролем от 12 символов. Сохраните `access_token`.
2. Передавайте `Authorization: Bearer <токен>` во всех дальнейших `/api` запросах.
3. `POST /api/sessions` с `{}`. `user_id` сервер берёт из токена.
4. `PATCH /api/sessions/<id>/config` с полным `config.request` по `configs/trip_request.schema.json`.
5. `POST /api/sessions/<id>/confirm` с `{}`.
6. `POST /api/sessions/<id>/search` с `{}`. Ответ содержит отдельные части маршрута, ошибки и ограничения.
7. `GET /api/sessions/<id>/routes` - последняя выдача. Правка конфига сбрасывает её и подтверждение.
8. `POST /api/auth/logout` отзывает токен. Повторный login также отзывает предыдущий токен пользователя.

В JSON-конфиге даты - `YYYY-MM-DD`, возраст детей - целые 0-17, суммы бюджета - основные единицы валюты. В выдаче `price.amount_minor` - строка int64 с копейками/центами; `price.scope` указывает, относится сумма к человеку, круговому билету или всем номерам за весь срок. Отсутствие цены не означает бесплатную услугу.

Полные тела запросов - в [API.ru.md](API.ru.md) и Swagger. Даты примера там фиксированы; для запуска после декабря 2026 их нужно обновить. Автоматические smoke/E2E используют даты относительно текущего дня.

## 6. Тестирование

```text
go run ./cmd/dev test -cover
go run ./cmd/dev e2e
```

Unit и интеграционные тесты проверяют все модули workspace. Это включает реальные сериализацию protobuf, gRPC-вызовы через bufconn, запросы к локальному TLS HTTP-серверу поставщика, HTTP middleware и хранилище. Проверяются не только успешные ответы, но и 400/401/403/404/409/429/5xx, таймауты, отмена, пустая выдача, подмена владельца, потеря полей и сбои записи.

E2E - backend API end to end: отдельные процессы, настоящие TCP-порты, HTTP → gateway → travel → provider/session/map/route. Тесты строят бинарные файлы в отдельной временной папке, выбирают свободные порты, создают отдельные аккаунты и гарантированно останавливают свои процессы. Нельзя считать это браузерным тестом frontend: интегрированный интерфейс отсутствует в этой ветке.

Покрытие: `reports/coverage.html` для просмотра строк, `reports/coverage.md` для сводки и `reports/unit.coverprofile` для инструментов Go. Порог - 80% statements по явно перечисленным файлам нашей реализации. Счётчики одинаковых блоков из нескольких интеграционных пакетов объединяются, а не складываются в завышенный процент. Сгенерированный код и исходные чужие заглушки не маскируют знаменатель; полный список включённых файлов - `internal/devtool/coverage.go`.

```text
go run ./cmd/dev test -race -cover
```

Для race нужен CGO и подходящий C-компилятор: Clang на macOS, GCC/Clang на Linux, совместимый MinGW/GCC на Windows. Обычные test/e2e C-компилятора не требуют. Ошибка отсутствия компилятора не означает ошибку проекта.

## 7. Что подтверждено на разных ОС

Нативный прогон в этой рабочей сессии доступен только на Windows. Для Linux amd64/arm64 и macOS Intel/Apple Silicon успешно выполнена кросс-компиляция: по семь бинарных файлов (runner и шесть сервисов) на каждую платформу. **Успешная кросс-компиляция не является выполнением тестов на другой ОС.**

`.github/workflows/verify.yml` задаёт реальные unit/integration/race/coverage/E2E на Windows, macOS и Linux и отдельный Docker smoke на Linux. Результаты выполнения доступны в GitHub Actions и проверках PR. Поддержку конкретной ОС подтверждает успешный нативный прогон соответствующей задачи.

## 8. Частые проблемы

| Симптом | Что проверить |
|---|---|
| `go` не найден | Go установлен и его bin входит в PATH; откройте новый терминал |
| «run inside repository» | Текущая папка содержит `go.work` и `ABOUT.md` |
| Загрузка модулей не проходит | Доступ к Go proxy, настройки корпоративного прокси; секреты проекта для загрузки модулей не нужны |
| «port unavailable» | Другой стек на порту; используйте `-random-ports` |
| Docker не подключается | Запущен daemon/Desktop и выбраны Linux-контейнеры |
| HTTP 401 | Токен отсутствует, отозван, истёк или заменён новым login |
| HTTP 404 для сессии | Чужая/несуществующая сессия либо session-service перезапущен: его память не сохраняется |
| HTTP 409 при поиске | Подтвердите текущий конфиг; после правок нужно подтвердить заново |
| `route-service: Unimplemented` | Части найдены и переданы; склейка этапа 3 ещё не реализована командой |
| `hotel/not_configured` в live | Реальный гостиничный адаптер не подключён; это явное ограничение |
| Тест не может слушать localhost | Среда/песочница блокирует loopback; тестам нужны локальные TCP-соединения |

## 9. Граница готовности

Реализованы авторизация, единая модель данных для нейронки, маппинг, прототип поиска и передача частей следующему этапу. Demo полностью воспроизводим без ключей. Не заявлены как готовые: реальные гостиницы, автоматический геокодинг, проверка live с ключами, LLM-диалог, склейка/ранжирование, frontend и покупка. Последние пункты относятся к другим этапам; первые три остаются ограничениями live-поиска нашей части.

Контекст сессий и выдача пока в памяти; аккаунты - в файле для одного gateway. Для публичного размещения нужен HTTPS перед gateway. Это прототип для хакатона, а не обещание production-готовности.
