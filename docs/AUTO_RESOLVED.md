# Автоматическое определение городов

Перед live-поиском SearchParts в provider-service разрешает названия origin, destination и stops через Travelpayouts places2. При наличии YANDEX_RASP_API_KEY координаты проверенного города используются для nearest_settlement Яндекса. Внешние запросы остаются в provider-service; маппинг получает уже проверенные коды.

Выбирается единственное точное совпадение названия с учётом country_code, если он указан. Служебный вес и порядок выдачи не используются. При отсутствии единственного совпадения возвращается ошибка places/clarification_required с предложением уточнить город и код страны. Коды для неоднозначного города не подставляются. Интерфейс показывает это как ошибку поиска; отдельная форма уточнения относится к следующему этапу.

SearchPartsResponse.resolved возвращает результат, включая частично полученные коды. Travel-service сохраняет его в TripConfig.resolved через session-service. Перед обращением к AI поле удаляется из конфига и истории. Изменение города или страны удаляет соответствующие коды; изменение бюджета сохраняет их. Изменение дат сбрасывает сохранённые даты гостиничного поиска.

Ответы справочников кэшируются в памяти процесса с cache_ttl_s из configs/providers.json. Запросы соблюдают rps и timeout_ms, отменяются вместе с исходным запросом. Ошибки не кэшируются. Перезапуск очищает кэш справочников, но сохранённый resolved остаётся в сессии. Demo-режим и live без транспортных ключей не обращаются к справочникам.

## Проверка

- make test: тесты всех модулей и vet прошли.
- make e2e: запуск полного стека, поиск, жизненный цикл заказа и остановка процессов прошли.
- Race-тесты providerkit, provider-service и travel-service прошли, включая кэш, неоднозначность, инвалидирование и сохранение resolved.
- Реальный Qwen → confirm → search через localhost:5173, без PATCH конфига и без передачи кодов: Москва MOW/c213, Париж PAR/c10502. Получено 30 кэшированных предложений Aviasales; коды сохранены в сессии.
- В этом прогоне Яндекс частично превысил тайм-аут, готовых кандидатов маршрутов не собрано. Это отдельное ограничение поиска: разрешение городов успешно. Детали — docs/evidence/main-check/moscow-paris.json.

Для live нужны TRAVELPAYOUTS_TOKEN и/или YANDEX_RASP_API_KEY в .env. После изменения кода: docker compose build provider-service travel-service gateway, затем PROVIDER_MODE=live docker compose up -d --no-deps provider-service travel-service gateway. Локальный запуск: make MODE=live.
