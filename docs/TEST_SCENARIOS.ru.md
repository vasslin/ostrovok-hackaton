# Сквозные тестовые сценарии «О!дин запрос»

Матрица предназначена для ручной приёмки по ТЗ трека и контракту фронтенда. Провайдерный слой находится в `main`; локальные изменения provider-service пока не закоммичены. `origin/frontend` остаётся отдельной демоверсией с синтетическими данными и локальным хранением. Настоящий AI, авторизация, серверное хранение, действующий поиск отелей и сквозная интеграция UI с провайдерами пока не подтверждены.

Проверки 28.10.2026 и их режимы записаны в [отчёте прогона](evidence/2026-10-28/RUN_REPORT.ru.md): в демо U01, U02 и U10 не прошли; U24 и U29 проверены частично. Отдельно выполнены проверки provider-service и маршрута gateway. Эти результаты не засчитываются как сквозной прогон интегрированного приложения.

Для каждого прогона записывайте дату, commit SHA, сборку, окружение, входной запрос, фактические реплики/события, итог, скриншот или лог без персональных данных. Статус `не запускался` ниже означает отсутствие ручного прогона, а не доказанную работоспособность. После проверки ставьте `пройден`, `не пройден` или `заблокирован` с причиной; не реализованный путь при попытке прогона считается заблокированным. Покрытие unit-тестами конфигов не засчитывает сквозной сценарий.

## Подготовка проверяемого демо

Зафиксируйте входные сообщения, дату/часовой пояс, конкретные fixture-ответы поставщиков и версии схем до записи видео. Для ошибок используйте управляемую инъекцию 429, timeout, пустого ответа, роста цены и повторного запроса; ожидание настоящей аварии внешнего API не воспроизводимо. В записи называйте режим (`standalone`, `demo`, `gateway`), источник каждой цены и действия, которые имитируются.

Короткий маршрут записи: U02 → U54 → U59 → U21 → U24 → U27 → U29; отдельные короткие фрагменты U17 и U69 показывают частичный сбой и проверку сложной стыковки. До интеграции соответствующих частей эту последовательность нельзя выдавать за пройденный сквозной тест.

## Критерии зачёта

- **Блокирующие:** ни одного молчаливого нарушения жёсткого ограничения; ни одной несовместимой стыковки в готовом плане; ни одного ложного статуса оплаты/брони; отсутствуют утечки секретов и реальные платёжные данные.
- **Основной путь:** от свободного запроса до понятного плана и mock checkout; каждое существенное решение объяснено, допущения можно исправить.
- **Устойчивость:** пустые/ошибочные ответы и повторы запросов не приводят к падению, двойному заказу или выдуманной информации.
- **Честность данных:** источник, свежесть и реальный/кэшированный/синтетический статус цены, расписания, погоды и отзыва видны пользователю.
- **Пересборка:** изменение условия сохраняет подходящие выбранные элементы и показывает состав/стоимость изменившихся частей.
