# Godnota - часть хакатона: поиск, авторизация, конфиги

Backend для **этапа 2 обработки запроса из ABOUT.md**: авторизация пользователя, единый конфиг поездки, маппинг и поиск предложений провайдеров.

## Запуск на macOS, Linux и Windows

Нужен **Go 1.26.5** и свободные порты 8080, 50051, 50052, 50054, 50056-50058. Из корня распакованного проекта в Terminal, Bash, PowerShell или cmd выполните одинаковую команду:

```text
go run ./cmd/dev run
```

Команда соберёт и запустит семь процессов: gateway, session-service, map-service, provider-service, route-service, travel-service и order-service. После сообщения `API: http://127.0.0.1:8080 mode: demo` откройте `http://127.0.0.1:8080/docs`. Ctrl+C завершает созданные процессы. Нужны интернет для первой загрузки Go-зависимостей и Go-компилятор; **PowerShell, Bash, Python, protoc и API-ключи для этого запуска не нужны**.

В другом терминале из корня проекта:

```text
go run ./cmd/dev smoke
```

Ожидается `PASS: register, mapping, session, confirmation, 4 transport / 1 hotel parts, logout`. Демо работает на явно помеченных **синтетических** предложениях.

Если порты заняты:

```text
go run ./cmd/dev run -random-ports
```

Используйте напечатанный URL и `go run ./cmd/dev smoke -url http://127.0.0.1:<порт>`.

## Запуск через Docker

На macOS/Windows нужен запущенный Docker Desktop с Linux-контейнерами; на Linux - Docker Engine и Compose v2.24+. Go на хосте для самого контейнерного запуска не нужен.

```text
docker compose up --build --wait
```

Проверка состояния: `docker compose ps`. Журнал: `docker compose logs --tail 100`. Остановка с сохранением аккаунтов: `docker compose down`. Секреты, данные и локальные исполняемые файлы исключены из Docker build context.

## Тесты

Команды одинаковы для всех ОС:

```text
go run ./cmd/dev test -cover
go run ./cmd/dev e2e
```

Первая запускает unit-тесты, интеграции через gRPC/HTTP, `go vet` и проверку покрытия кода нашей части с порогом 80%. Отчёты: `reports/coverage.md`, `reports/coverage.html`, `reports/unit.coverprofile`. Из знаменателя явно исключены сгенерированный protobuf, инструменты запуска и чужие исходные заглушки; список файлов виден в `internal/devtool/coverage.go`.

Вторая команда **сама** собирает и запускает семь сервисов на свободных портах, проверяет публичный HTTP API в demo и обработку отсутствующих ключей в live, затем останавливает процессы. Никакие внешние API при E2E не вызываются. Уже запущенный локальный стек не нужен.

## Что реализовано

- Регистрация, login/me/logout, безопасное хранение паролей и отзываемые Bearer-токены.
- Проверка доступа к сессиям, профилям и заказам; владелец новой сессии берётся из токена.
- Сессии, сохранение и подтверждение конфига, поиск и кэш выдачи; правки сбрасывают подтверждение и результат.
- Единый `TripRequest` и контракт ответа AI; независимая проверка конфига backend.
- Маппинг в запросы транспорта и гостиниц через gRPC и `POST /api/providers/map`.
- Параллельный поиск, таймауты, отмена, RPS, частичные ошибки и нормализация предложений с источником и единицей цены.
- Передача найденных частей в `route-service.BuildRoutes`. Отказ/неготовность следующего этапа не уничтожает выдачу этапа 2.

## Полностью ли готова часть

**Для проверяемого прототипа с демоданными реализованы авторизация, конфиг/маппинг и поиск частей маршрута. Называть готовой полную live-интеграцию пока нельзя.**

Адаптер Hotelbeds подключён к `SearchParts` в live-режиме и проверен через gateway с evaluation-данными; это не live-бронирования. Сервис маршрутов детерминированно собирает совместимые варианты и возвращает их через gateway: [контракт и ограничения](docs/route/README.md). Проверки приведены в [протоколе](docs/evidence/2026-10-28/RUN_REPORT.ru.md). AI-ранжирование, автоматическое разрешение городов, полноценный frontend/браузерный E2E и настоящие бронирования остаются незавершёнными.

Аккаунты сохраняются в `data/auth.json` (в Docker - volume). Контекст сессий, выдача и демозаказы пока находятся в памяти; после перезапуска они теряются. Профили остаются заглушками. Файловое хранилище аккаунтов рассчитано на один gateway.

Подробный гайд, сценарии, архитектура и честная матрица проверки ОС - [docs/GUIDE.ru.md](docs/GUIDE.ru.md). Детали HTTP/gRPC и границы этапов - [docs/API.ru.md](docs/API.ru.md).
