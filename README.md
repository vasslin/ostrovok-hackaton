# О!дин запрос

Объединённый проект: интерфейс, gateway, AI, контекст сессий, поставщики, сборка маршрутов и демозаказы. В режиме `demo` **Qwen настоящий**, а цены, билеты и отели синтетические. Оплата и бронирование также демонстрационные.

## Запуск на своём компьютере

Нужны Go 1.26.5+ и Ollama. Node.js, Python и protoc для запуска через Go не требуются. Для Qwen3 4B ориентируйтесь на 16 GB RAM; скорость зависит от оборудования. Установите Ollama по [LOCAL_QWEN.md](LOCAL_QWEN.md), затем из корня проекта:

```sh
ollama pull qwen3:4b
ollama create travel-qwen:4b -f ai-service/ollama/Modelfile
```

Ollama должен работать: приложение Ollama на Windows/macOS или `ollama serve` в отдельном терминале. Если `.env` отсутствует, его можно создать копированием `.env.example`; все значения в примере пустые, локальные настройки уже заданы в приложении.

```sh
make doctor
make
```

Откройте **http://localhost:5173**. Gateway: http://127.0.0.1:8080/docs. Прямой Swagger AI: http://127.0.0.1:8090/docs. Ctrl+C останавливает все дочерние сервисы и UI; Ollama остаётся работать отдельно. Нативный запуск хранит контекст и демозаказы в памяти, аккаунты — в `data/auth.json`.

Без make, в том числе в Windows PowerShell, работают те же команды:

```text
go run ./cmd/dev doctor
go run ./cmd/dev run -full
```

При занятых портах: `make RUN_FLAGS=-random-ports` или `go run ./cmd/dev run -full -random-ports`; используйте напечатанный адрес UI. Пользовательские порты: `make WEB_PORT=5174 AI_HTTP_PORT=8091`. Конфигурация: `ENV_FILE=...`; переменные окружения имеют приоритет над файлом. Логи — `data/logs/`.

## Docker

Нужны Docker Engine/Desktop и Compose 2.24+. Ollama запускается **на хосте**; особенно на macOS это позволяет использовать Metal. Модель не включена в Git или Docker-образ и устанавливается отдельно на машине, выполняющей AI.

```sh
docker compose up --build -d --wait
```

Тот же UI: http://localhost:5173. Compose запускает все сервисы и PostgreSQL; история/конфиг сохраняются в volume `session-data`, аккаунты — в `auth-data`. `docker compose down` останавливает стек с сохранением volumes. Для Linux настройка доступа контейнера к Ollama описана в LOCAL_QWEN.md.

## Ключи для организаторов

В корне хранится бинарный `secrets.env.age`, зашифрованный публичным ключом организаторов. Исходный `.env.jury` и локальный `.env` исключены из Git и Docker build context; `.env.example` содержит только пустые значения. После изменения настроек выполните `./scripts/encrypt-secrets.sh`. Расшифровка доступна владельцу закрытого ключа организаторов; подробности — [docs/SECRETS.md](docs/SECRETS.md).

Основной AI — **Ollama**, модель **travel-qwen:4b** на основе Qwen3 4B. В этом режиме LLM-ключ не используется. Облачная альтернатива — **Groq**, модель **openai/gpt-oss-20b**; для неё нужны отдельный ключ жюри и согласованные `LLM_PROVIDER`, `LLM_BASE_URL`, `LLM_MODEL`. Ранее опубликованные ключи необходимо перевыпустить: шифрование не устраняет прежнюю утечку.

## Проверка

```sh
make build
make test
make e2e
make smoke
make test-ai
```

`make test` проверяет все Go-модули и запускает vet. `make e2e` поднимает изолированные процессы и проверяет авторизацию, права владельца, выдачу кандидатов, несколько городов, демозаказ/повтор/оплату/отмену и остановку полного стека. Внешние LLM при этом не вызываются.

`make smoke` проверяет уже запущенный gateway. **`make test-ai` вызывает настоящую модель** через gateway: уточнения → ответы → сохранённый конфиг → подтверждение → поиск. Для другого порта задайте `API_URL`, например `make test-ai API_URL=http://127.0.0.1:12345`; можно передать адрес UI, чтобы проверить и его прокси. Эти проверки создают только синтетические тестовые аккаунты и сессии.

Без make: `go run ./cmd/dev build`, `go run ./cmd/dev test`, `go run ./cmd/dev e2e`, `go run ./cmd/dev smoke`, `go run ./cmd/dev ai-smoke`. Проверка гонок: `go run ./cmd/dev test -race`. Для frontend-тестов нужен Node.js 20+: `cd frontend`, затем `npm test` и `npm run check`.

## Что показать

Зарегистрируйтесь в UI, отправьте «Хочу из Москвы в Сочи. Даты и состав пока уточняем». Ответьте на вопросы: «С 10 по 17 ноября 2026, двое взрослых, бюджет 80000 рублей». Проверьте состав группы, маршрут, источники и предупреждения. Выбор вариантов ограничен совместимыми кандидатами из backend. Кнопка оформления создаёт демозаказ через `/api/orders`, реальных платежей нет. Для другого дня обновите даты.

Qwen интерпретирует сообщение и уточнения; код проверяет обязательные поля, даты и деньги. Route-service детерминированно собирает и упорядочивает варианты. AI API ранжирования доступен отдельно, но сортировка кандидатов в основном сценарии пока детерминированная. Полноценное редактирование профиля и серверный список истории поездок frontend пока не интегрированы. UI хранит ссылки на созданные заказы в этом браузере и проверяет их через API заказов; история с другого устройства автоматически не появляется.

## Другой компьютер

При самостоятельном запуске друг скачивает модель в **свой** Ollama, создаёт `travel-qwen:4b` и выполняет команды выше. После загрузки локальному AI не нужны VPN, ключ LLM или дневная квота; доступность первоначального скачивания зависит от сети. Другой вариант — открыть UI уже работающего сервера: тогда модель нужна только серверу, не телефону/ноутбуку клиента. Подробнее: [LOCAL_QWEN.md](LOCAL_QWEN.md).
